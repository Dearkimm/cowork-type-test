# cowork-type-test

협업 성향을 검사하고, 같이 일할 사람들과의 궁합을 보는 웹 서비스입니다.

한 사람이 검사를 마치면 공유 URL이 생기고, 그 링크를 팀원들에게 뿌리면 길드가 하나 만들어집니다. 사람이 들어올 때마다 팀 결과가 갱신됩니다.

## 1. 설계 원칙

이 프로젝트가 기존 성향 테스트들과 다르게 가려는 지점입니다. 구현 중에 흔들리기 쉬운 부분이라 먼저 적어둡니다.

**유형 라벨을 만들지 않습니다.**
MBTI나 DiSC처럼 "당신은 D형입니다"로 끝내지 않고 서술로 내보냅니다. 이유는 세 가지입니다. 51:49로 갈린 사람과 90:10인 사람이 같은 라벨을 받게 되어 정보가 날아갑니다. 라벨은 자기 방어 도구가 되어 "난 원래 이런 유형이라"로 쓰입니다. 그리고 궁합 계산에 불리합니다. 유형이 4개면 조합 해설을 16개 손으로 써야 하는데, 축 점수를 그대로 두면 계산으로 나옵니다.

**결과는 판정이 아니라 규칙 제안입니다.**
연애 궁합은 안 맞다고 나와도 웃고 넘기지만, 협업은 그 사람과 실제로 일해야 합니다. "두 분은 안 맞습니다"가 아니라 "이 조합에서는 착수 전에 산출물 형태를 정해두시는 게 좋습니다"로 씁니다. 같은 데이터로 완전히 다른 제품이 됩니다.

**개인 결과는 [나 사용법]으로 씁니다.**
자기 이해로 끝나는 문장이 아니라, 남이 나를 다룰 때 참고하는 문장으로 씁니다. 내 성격 분석은 나만 재미있지만 나 사용법은 팀원에게 보낼 이유가 됩니다. 공유 동기를 문구 설계로 만드는 것입니다.

**척도 대신 강제선택을 씁니다.**
5점 척도는 사람마다 응답 폭이 달라서, 성향이 아니라 응답 습관 때문에 궁합이 달라집니다. 실제로 초기 테스트에서 한 응답자가 2·3·4에만 몰려 답한 사례가 나왔습니다. 두 문장 중 하나를 고르게 하면 이 편차가 생기지 않습니다.

**궁합은 축마다 방향이 다릅니다.**
사주 궁합은 대체로 "비슷하면 좋다"로 계산하지만 협업은 아닙니다. 리듬에 해당하는 축은 같아야 좋고, 역할에 해당하는 축은 달라야 좋습니다. 이걸 단순 유사도로 계산하면 틀린 답이 나옵니다.

**길드는 열리고 닫히는 게 아니라 자랍니다.**
팀원 전원이 끝낼 때까지 결과를 잠그면 두 번째 사람에서 흐름이 끊깁니다. 혼자여도 개인 서술이 나오고, 두 명이면 마찰 지점이 나오고, 세 명 이상이면 팀에서 비어 있는 축이 나옵니다. 사람이 늘 때마다 결과가 달라지니 다시 볼 이유도 생깁니다.

## 3. 스택

- Next.js, Vercel 배포
- DB는 응답과 길드를 누적해야 하므로 필요합니다. 정적 사이트로는 안 됩니다.
- 결과 문구에 LLM을 쓰지 않습니다. 같은 답에 같은 결과가 나와야 하고, 응답 하나당 비용이 붙으면 안 됩니다. 전부 계산과 조건 분기입니다.
- 본문은 프리텐다드, 일본어는 프리텐다드 JP, 픽셀 글꼴은 갈무리11입니다. 한국어 제목용 글꼴은 아직 정하지 않았습니다.

## 4. 디자인 방향

라이트 파스텔을 바탕으로 두고 비비드는 강조에만 씁니다. 픽셀 아트가 기본 재료입니다.

- 배경은 파스텔 그라데이션. 장이 넘어갈 때 색이 바뀝니다.
- 장식은 전부 픽셀로 찍습니다. 무지개와 날개는 격자를 손으로 그리는 대신 곡선을 계산해서 찍습니다.
- 알약·캡슐 모양, 카드 나열, 누런톤은 쓰지 않습니다.
- 캐릭터를 골라 커서로 쓰고, 나중에 팀에서 누가 누구인지 구분하는 표시가 됩니다.
- 모서리는 각지게 하지 않고 둥글게 둡니다.

## 5. 현재 상태

문항 30개, 채점 규칙, 개인 결과 화면까지 돌아갑니다. 검사 화면은 게임 창 틀 버전([prototype/game.html](prototype/game.html))으로 가는 중이고, 기존 버전을 비교용으로 남겨 두었습니다.

남은 것은 이렇습니다.

- 팀 결과 화면. 혼자·둘·셋넷에서 내용이 달라야 합니다
- 조합 규칙을 30~40개까지 늘리기 (현재 20개)
- 축 1·2 규칙을 실제 응답으로 검증
- 캐릭터 그림을 PNG로 교체 ([prototype/sprites/](prototype/sprites/))
- Next.js와 DB로 옮기기. 지금은 결과를 URL에 싣고 있어서 팀이 커지면 한계가 있습니다
