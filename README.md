# 오시에테 (おしえて)

협업 성향을 검사하고, 같이 일할 사람들과 서로의 [사용법]을 맞춰 보는 웹 서비스입니다.

30문항을 마치면 유형 이름이 붙은 개인 결과와 공유 URL이 나옵니다. 팀은 최대 네 명이고, 팀 하나에 URL이 하나 생겨서 사람이 들어올 때마다 팀 결과가 갱신됩니다. 팀 화면 1차가 본편에 붙어서 만들기 → 초대 → 합류까지 실서비스에서 돌아갑니다 (08-01).

배포 주소는 <https://oshiete-test.vercel.app> 입니다.

## 1. 설계 원칙

이 프로젝트가 기존 성향 테스트들과 다르게 가려는 지점입니다. 구현 중에 흔들리기 쉬운 부분이라 먼저 적어둡니다.

**유형 이름은 손잡이, 본체는 서술입니다.**
처음에는 라벨을 아예 만들지 않는 것이 원칙이었습니다. 51:49로 갈린 사람과 90:10인 사람이 같은 라벨을 받으면 정보가 날아가고, 라벨은 "난 원래 이런 유형이라"는 방어 도구가 되기 때문입니다. 그런데 공유하는 쪽에 서서 보니 "나 이거 나왔어"라고 부를 이름이 없으면 말이 퍼지지 않았습니다. 그래서 이름을 도입하되 역할을 좁혔습니다. 이름은 서술과 별개로 짓는 게 아니라 축의 극 문구에서 조립합니다 — 가장 치우친 축이 명사, 두 번째 축이 수식어, 총 91가지입니다. 명사 열 개에는 픽셀 아이템이 하나씩 붙습니다. 상세 서술과 실제로 고른 답 인용은 이름과 무관하게 그대로 나갑니다. 전체 목록은 [docs/type-names.md](docs/type-names.md)에 있습니다.

**결과는 판정이 아니라 규칙 제안입니다.**
연애 궁합은 안 맞다고 나와도 웃고 넘기지만, 협업은 그 사람과 실제로 일해야 합니다. "두 분은 안 맞습니다"가 아니라 "이 조합에서는 착수 전에 산출물 형태를 정해두시는 게 좋습니다"로 씁니다. 같은 데이터로 완전히 다른 제품이 됩니다.

**개인 결과는 [나 사용법]으로 씁니다.**
자기 이해로 끝나는 문장이 아니라, 남이 나를 다룰 때 참고하는 문장으로 씁니다. 내 성격 분석은 나만 재미있지만 나 사용법은 팀원에게 보낼 이유가 됩니다. 공유 동기를 문구 설계로 만드는 것입니다.

**척도 대신 강제선택을 씁니다.**
5점 척도는 사람마다 응답 폭이 달라서, 성향이 아니라 응답 습관 때문에 궁합이 달라집니다. 실제로 초기 테스트에서 한 응답자가 2·3·4에만 몰려 답한 사례가 나왔습니다. 두 문장 중 하나를 고르게 하면 이 편차가 생기지 않습니다.

**궁합은 축마다 방향이 다릅니다.**
사주 궁합은 대체로 "비슷하면 좋다"로 계산하지만 협업은 아닙니다. 리듬에 해당하는 축은 같아야 좋고, 역할에 해당하는 축은 달라야 좋습니다. 이걸 단순 유사도로 계산하면 틀린 답이 나옵니다.

**팀은 열리고 닫히는 게 아니라 자랍니다.**
팀원 전원이 끝낼 때까지 결과를 잠그면 두 번째 사람에서 흐름이 끊깁니다. 혼자여도 개인 서술이 나오고, 두 명이면 쌍 규칙이 나오고, 세 명 이상이면 축 규칙으로 갑니다. 바통 릴레이(한 사람이 끝내고 다음 사람에게 링크를 넘기는 방식)는 쓰지 않습니다 — 중간에 한 명이 멈추면 뒤가 전부 끊깁니다. 대신 팀 하나에 URL 하나를 두고, 누가 언제 들어와도 같은 주소를 씁니다.

## 2. 지금 어디까지 왔나

혼자 쓰는 구간은 끝까지 돌아갑니다.

- 랜딩 — 그림 한 장짜리 배경, 픽셀 레터링 제목, 캐릭터 넷(멍멍이·고양이·토끼·햄스터) 중 선택
- 검사 — 30문항 강제선택. 게임 창 틀에 5문항마다 배경색이 바뀌고, 반환점을 넘으면 캐릭터에 땀방울이 맺힙니다. 중도이탈을 줄이려고 첫 다섯 문항은 가장 가벼운 것들로 배치했습니다
- 개인 결과 — 유형 이름과 아이템, 요약 문장, 축별 서술, 실제로 고른 답 인용, 축 조합 규칙(현재 36개)
- 공유 — 결과가 URL 해시에 실립니다. 서버가 없어서 링크만으로 결과가 열립니다

팀도 만들기부터 합류까지 한 바퀴가 돌아갑니다 (08-01).

- 개인 결과의 [팀 만들기] → 방장이 팀 이름을 짓고 → `#t=<아이디>` 팀 URL이 생깁니다. 팀 페이지의 [나도 참여하기] → 캐릭터·이름 → 검사 → 개인 결과를 본 뒤 [팀 화면 보기]로 넘어가는 흐름이고, 합류는 검사가 끝날 때 뒤에서 끝납니다
- 화면은 인원수를 따라갑니다. 혼자면 자리 넷과 초대 링크만, 둘이면 쌍 규칙 다섯 개가 바로 열리고, 셋부터는 그래프(강조 두 쌍)가 문이 되어 길을 누르면 그 두 사람의 이야기가 나옵니다
- 같은 이름은 별명 입력에서 막습니다. 그래서 [같은 이름 재검사는 덮어쓴다] 갱신 경로의 입구가 사라졌는데, 재검사 갱신 UI는 따로 만들어야 합니다
- 저장소는 MongoDB Atlas 무료 티어입니다. 팀 하나 = 문서 하나이고, 마지막 활동 90일 뒤 자동 삭제됩니다 (보관 3개월 결정)
- `api/team.js` 가 만들기·읽기·합류를 받습니다. 4명 제한, 이름 키, 원점수 미수신까지 실서버에서 검증했습니다
- 남은 팀 문구: 팀 한 줄은 미작성이라 생략했고, 셋넷용 팀 축 규칙은 축 1만 문구가 있어 축 2~5는 분포 + [준비 중]로 나갑니다
- 결과 문장은 전수 검토 중입니다. 1차 판정과 07-31 일괄 수정(하루 묵히기·~쪽·지시형 제거)을 반영했고, 2차 검토표 [docs/copy-review-r2.md](docs/copy-review-r2.md)의 판정 칸을 채우면 다시 반영합니다

## 4. 스택

- 화면은 `prototype/index.html` 한 파일을 Vercel에 정적 배포합니다. 빌드 도구가 없습니다
- 팀 저장은 MongoDB Atlas(무료 티어) + `api/` 의 Vercel 함수입니다. 연결 문자열은 Vercel 환경 변수 `MONGODB_URI`에만 있고 레포에는 없습니다
- 화면이 더 커지면 Next.js로 옮깁니다
- 결과 문구에 LLM을 쓰지 않습니다. 같은 답에 같은 결과가 나와야 하고, 응답 하나당 비용이 붙으면 안 됩니다. 전부 계산과 조건 분기입니다
- 본문은 프리텐다드, 일본어는 프리텐다드 JP, 픽셀 글꼴은 갈무리11입니다. 한국어 제목용 글꼴은 아직 정하지 않았습니다

## 5. 디자인 방향

라이트 파스텔을 바탕으로 두고 비비드는 강조에만 씁니다. 픽셀 아트가 기본 재료입니다.

- 장식은 전부 픽셀로 찍습니다. 안경·곡괭이처럼 곡선이 들어가는 건 격자를 손으로 그리지 않고 계산해서 찍습니다 (해결사는 활→안경, 세공사는 망치→보석으로 교체 — 망치가 세공으로 안 읽혔습니다)
- 아이템 열 개는 장비 아이콘 규칙으로 그립니다 — 1px 진한 외곽선, 좌상단 광원, 우하단 그늘, 안티앨리어싱 없음. 다만 실루엣이 안 읽히면 규칙보다 알아보기를 우선합니다
- 알약·캡슐 모양, 카드 나열, 누런톤, 각진 모서리는 쓰지 않습니다
- 캐릭터와 아이템은 팀 화면에서 "누가 누구인지"를 구분하는 표시가 됩니다
- 아이콘 점검은 <https://oshiete-test.vercel.app/#items> 로 엽니다. 열 개가 이름표와 함께 깔립니다
