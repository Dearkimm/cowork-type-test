# 이어서 작업하기

다른 PC에서 이 프로젝트를 이어받을 때 먼저 읽는 문서입니다. 마지막 갱신은 2026-07-29입니다.

## 1. 받아서 열기

```bash
git clone https://github.com/Dearkimm/cowork-type-test.git
cd cowork-type-test
```

설치할 것도, 빌드할 것도 없습니다. `prototype/game.html`을 브라우저로 바로 열면 그게 현재 화면입니다.

**프로토타입 두 개는 각각 그 자체가 원본입니다.** 다른 파일에서 생성하는 구조가 아니니 파일을 직접 고치시면 됩니다. 폰트가 CDN 링크로 걸려 있어서 인터넷이 연결돼 있어야 픽셀 글꼴이 제대로 보입니다.

| 파일 | 무엇 |
|---|---|
| `prototype/game.html` | 지금 가고 있는 방향. 검사 화면이 게임 창 틀입니다 |
| `prototype/index.html` | 비교용으로 남긴 이전 버전. 방향이 정해지면 지웁니다 |
| `prototype/fonts.html` | 한국어 제목 글꼴 비교용. 아직 안 정했습니다 |
| `prototype/sprites/` | 캐릭터 PNG 넣는 곳. 넣으면 코드 격자 대신 그 그림을 씁니다 |

두 파일은 랜딩·캐릭터 선택·결과 화면이 같은 코드이고 **검사 화면만** 다릅니다.

## 2. 어디까지 됐나

돌아가는 것

- 랜딩 → 캐릭터 선택 → 30문항 → 개인 결과까지 한 번에 통과합니다
- 문항 30개, 5축 채점, 결과 문구 조립(축별 서술 + 조합 규칙 + 조언)이 다 붙어 있습니다
- 결과가 URL 해시에 실려서 링크를 보내면 그 결과가 다시 그려집니다
- 캐릭터를 고르면 마우스 커서가 그 캐릭터로 바뀝니다

아직 없는 것

- **팀 결과 화면.** 개인 결과까지만 있습니다
- 캐릭터 PNG. 지금은 코드에 박힌 20×20 격자를 그려 쓰고 있습니다
- 한국어 제목 글꼴. 지금은 프리텐다드 900입니다

## 3. 정해진 것 — 뒤집지 말 것

이 결정들은 이유가 있어서 정해진 것입니다. 자세한 근거는 [spec.md](spec.md)에 있습니다.

- **유형 라벨을 만들지 않습니다.** 결과는 서술로만 냅니다
- **결과는 판정이 아니라 규칙 제안입니다.** 궁합 퍼센트를 내지 않습니다
- **선택지 두 쪽 중 한쪽이 착하거나 성실해 보이면 안 됩니다.** 긍정과 부정으로 읽히는 순간 답이 긍정 쪽으로 쏠립니다
- **답은 두 문장 × 두 단계입니다.** 중간값을 두지 않습니다. 1~5 척도로 돌아가면 응답 습관이 결과를 갈라 버립니다
- **문항은 축을 섞어서 냅니다.** 축별로 묶으면 응답자가 무엇을 재는지 알아차려 몰아서 답합니다
- **축 이름을 화면에 노출하지 않습니다.** 상황 구절로만 씁니다
- **결과 문구에 LLM을 쓰지 않습니다.** 전부 계산과 조건 분기입니다
- **팀은 방장 포함 최대 네 명입니다**
- **개인 원점수는 본인만 봅니다**
- **정답 연출을 넣지 않습니다.** 잘한 답이 있는 것처럼 보이면 답을 꾸미기 시작합니다

화면 쪽

- 라이트 파스텔이 바탕, 비비드는 강조에만
- 장식은 전부 픽셀. 무지개와 날개는 곡선을 계산해서 찍습니다
- 알약·캡슐 모양, 카드 나열, 누런톤, 모노스페이스 라벨은 쓰지 않습니다
- 모서리는 둥글게 둡니다

## 4. 다음에 할 일

순서대로입니다.

1. **팀 결과 화면.** 개인 결과 화면에서 초대 링크를 만드는 흐름입니다. 사람 수에 따라 내용이 달라야 합니다
   - 혼자 — 자리 넷과 초대 링크만. 판정 칸을 만들지 않습니다. 잠긴 칸도 두지 않습니다
   - 둘 — 쌍 규칙으로 축 다섯 개를 다 내보냅니다. `손발이 맞는 축 n / 5`
   - 셋·넷 — 쌍 규칙을 버리고 축 규칙으로 갑니다. 팀에 [높음]이 있는지, [높음]과 [낮음]이 섞여 있는지
   - 개인 화면에 있는 축 막대는 팀 화면에 두지 않습니다
   - **정하고 시작해야 하는 것**: 구간(높음·중간·낮음)을 팀에 보여줄지. 원점수는 어느 쪽이든 안 보입니다
2. **조합 규칙 늘리기.** 현재 20개, 30~40개까지. 실감은 축 하나하나의 서술이 아니라 축 사이 상호작용에서 나옵니다
3. **축 1·2 규칙 검증.** 초기 응답이 축 3·4·5만 다루고 있어서 이 둘은 아직 검증이 안 됐습니다
4. **캐릭터 PNG 교체.** `prototype/sprites/README.md`에 조건이 적혀 있습니다
5. **Next.js + DB로 옮기기.** 지금은 결과를 URL에 싣고 있어서, 팀이 커지면 마지막에 들어온 사람만 전체를 봅니다

## 5. Vercel에 올리기

정적 HTML이라 지금 바로 올라갑니다. 빌드 설정이 필요 없습니다.

1. vercel.com → Add New Project → `Dearkimm/cowork-type-test` 가져오기
2. **Root Directory를 `prototype` 으로 지정합니다.** 이게 핵심입니다. 비워 두면 레포 루트에 `index.html`이 없어서 아무것도 안 뜹니다
3. Framework Preset은 Other, 빌드 명령은 비워 둡니다
4. Deploy

올라간 뒤 주소는 이렇습니다.

- `/` → `prototype/index.html` (이전 버전)
- `/game.html` → 게임 틀 버전

방향이 정해지면 그 파일을 `index.html`로 바꿔서 `/`에 오게 합니다.

그 뒤로는 main에 푸시할 때마다 자동으로 다시 뜹니다.
