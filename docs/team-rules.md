# 팀 결과 설계 + 쌍 규칙 (초안)

## 팀 결과 구성 (07-31 제나 방향 확정)

팀 결과가 최우선이고, 쌍은 보조입니다. 화면은 세 층입니다.

1. **팀 한 줄** — 팀 이름 아래. 축 분포에서 가장 튀는 특징 하나를 담백하게. 은유 금지
2. **팀 축 규칙 다섯 개** — 본편. 축마다 팀 분포 모양(쏠림·외톨이·양극·분산)을 보고 문구를 냅니다
3. **쌍 그래프** — 여섯 쌍이 다 보이되, 두 쌍만 강조합니다
   - [합이 잘 맞는 조합] 하나 — 구간이 같은 축이 가장 많고 정반대 축이 없는 쌍
   - [규칙을 먼저 정하면 좋은 조합] 하나 — 정반대(높낮) 축이 가장 많은 쌍
   - 강조는 표시까지만 하고 등급·점수는 안 씁니다 (판정 금지 원칙 유지)
   - 나머지 쌍은 흐리게 두고, 누르면 세부 규칙이 열립니다

## 문구 결 (07-31 제나 피드백으로 확정)

제나가 좋다고 집은 문장들의 공통점을 규칙으로 만듭니다.

> 조사는 많이 해놓고 결과물은 무르게 나오는 패턴이 생기기 쉽습니다.
> 알려주면 만족하고, 안 알려주면 불안해하는데, 알려준 다음에 손대지는 않습니다.
> 문서화 같은 협의는 거의 마찰 없이 될 것입니다. 서로 알려주는 걸 귀찮아하지 않는 조합입니다.

- **행동 패턴을 예측합니다.** 조건→결과 구조가 제일 잘 먹힙니다 (알려주면 ~하고, 안 알려주면 ~합니다)
- **실무 명사를 씁니다.** 조사, 결과물, 문서화, 회의록, 공유 — 손에 잡히는 단어
- **본인 답을 복창하지 않습니다.** "둘 다 그 자리에서 말합니다"는 본인들이 이미 아는 사실
- **은유·수사 금지.** "마지막에 말한 사람이 결정한 것처럼 끝납니다" 같은 문장은 무슨 뜻인지 한 번에 안 읽힘 (07-31 기각). 뜻을 풀어서 씁니다: "각자 자기가 말한 결론으로 기억하고 흩어집니다"
- **과장·오글 금지.** "이 사람이 말하면 모두가 주목합니다" 계열 (07-31 기각)

copy-review.md 1차 판정(07-31)에서 추가된 규칙입니다.

- **금지어**: [대목] → 항목·문항, [같은 쪽] → 같은 방향, [축] 은 사용자 화면 문구에서 노출 금지 → 항목·상황, [결정이 굳는다] 같은 어색한 표현, [아무의 일도 아닙니다]·[하루 묵히는] 같은 비유 관용구
- **사용법 문구는 압축 명령형이 아니라 정중한 완결형으로.** "먼저 묻지 않는 편입니다. 필요한 보고는 알아서 올려주세요" (기각) → "상대의 자율에 온전히 맡기는 편입니다. 도움이 필요할 때 먼저 공유해 주면 충분합니다" (제나 재작성)
- **주인공 프레이밍 금지.** "이 사람이 강하게 말할 때는 실제로 중요한 안건일 가능성이 높습니다" 처럼 그 사람을 무대에 올리는 문장 (07-31 기각)
- **올라운더는 [빈 자리를 메우는] 결이 아니라 [어디에나 잘 어울리는] 결로.** 버리는 카드처럼 읽히면 안 됩니다

| 외톨이 · 혼자 먼저 말함 | 회의가 ○○ 님 의견 위주로 정리되기 쉽습니다. 나머지가 조용한 것이 동의라서인지 정리 중이라서인지는 물어보기 전엔 모릅니다. 결정 전에 돌아가며 한 마디씩 받는 순서를 넣으면 나머지 의견도 자리를 얻습니다. |
| 양극·분산 | 먼저 말하는 사람과 듣고 정리하는 사람이 다 있는 팀입니다. 회의 자리에서는 말하는 사람의 의견이, 하루 지나면 듣는 사람의 의견이 나옵니다. 그날 결정할 것과 다시 논의할 것을 나누기만 하면 양쪽 의견이 다 들어옵니다. |

### 쌍 규칙 재작업 — 축 1

| 조합 | 문구 |
|---|---|
| 높높 | 결론은 빨리 납니다. 대신 한 사람이 의견을 접어서 끝난 안건은 사라진 게 아니라서, 다음 회의에 같은 안건이 다시 올라오는 패턴이 생기기 쉽습니다. 결정 전에 각자 근거를 한 번씩 말하는 순서를 정해 두면 의견을 접었던 사람도 할 말을 하고 끝납니다. |
| 높중 | 평소에는 먼저 말하는 사람이 정하고 중간인 사람이 따라가는 흐름으로 굴러갑니다. 중간인 사람은 의견이 없는 게 아니라 고른 뒤에 말하는 편이라, 물어보면 나오고 안 물어보면 안 나옵니다. 결정 전에 한 번 지목해서 물으면 충분합니다. |
| 높낮 | 회의록만 보면 한 사람 의견으로 굴러가는 팀처럼 보이게 됩니다. 듣는 사람은 그 자리에서 정리가 안 끝나서 말을 아끼는 것이지 동의한 게 아닙니다. 결정을 바로 확정하지 않고 한 번 더 검토하는 시간을 두면, 듣는 사람의 의견이 정리되어 들어옵니다. |
| 중중 | 평소에는 조용히 굴러가고, 둘 다 입을 여는 안건이 실제로 중요한 안건입니다. 대신 애매한 안건은 서로 상대가 말하겠지 하고 넘기기 쉬우니, 그런 것만 누가 짚을지 정해 두는 것으로 충분합니다. |
| 중낮 | 부딪힐 일은 거의 없지만, 정하자고 먼저 나서는 사람도 없어서 결정이 늦어집니다. 마감일을 명확히 설정해 두고 다수결 투표나 정해진 체크리스트에 따라 결정하면 논의가 길어지는 것을 방지할 수 있습니다. |
| 낮낮 | 서로 말을 끊을 일은 없는 조합입니다. 대신 둘 다 상대 이야기를 다 듣고 나서 정리하는 편이라, 회의가 끝나도 결정은 안 나 있는 날이 생깁니다. 이번 건을 정하는 담당을 번갈아 맡으면 결정이 밀리지 않습니다. |

# 팀 쌍 규칙 (초안 — 재작업 전 버전)

두 사람일 때 축마다 한 단씩 내는 문구입니다. 구간 조합이 높음·중간·낮음에서 여섯 가지라, 축 다섯에 서른 개입니다. 검토 후 `prototype/index.html`에 박습니다. **아래 축 2~5 표는 옛 톤에 07-31 일괄 수정(하루 묵히기·~쪽·지시형 제거)만 반영한 것이고, 위 샘플 톤이 확정되면 전부 다시 씁니다.**

쓰면서 지킨 것입니다.

- 판정이 아니라 규칙 제안으로 끝냅니다. 궁합 점수를 내지 않습니다
- 어느 조합도 좋은 조합·나쁜 조합으로 읽히면 안 됩니다. 조합마다 굴러가는 방식과 걸리는 지점, 그걸 다루는 규칙 하나를 적습니다
- 높음·낮음 어느 쪽도 착해 보이면 안 됩니다

표기: 높높 = 두 사람 다 높음, 높낮 = 한쪽 높음 한쪽 낮음.

## 1 · 의견이 갈릴 때 (먼저 듣는 ↔ 먼저 말하는)

옛 톤 표는 지웠습니다. 위의 [쌍 규칙 재작업 — 축 1] 표가 이 축의 현재 문구입니다 (검토표 88~93번이 82~87번으로 대체).

## 2 · 일과 사람 사이 (사람을 먼저 보는 ↔ 일을 먼저 보는)

| 조합 | 문구 |
|---|---|
| 높높 | 둘 다 결과부터 봅니다. 용건만 오가도 서로 편하고 속도가 납니다. 대신 둘 다 분위기를 안 살피는 편이라, 팀에 다른 사람이 있으면 그 사람이 지치는 것을 늦게 알아차립니다. |
| 높중 | 일을 먼저 보는 사람의 담담한 말투를 중간인 사람이 무리 없이 받아서 마찰이 적습니다. 급한 시기에는 동료를 챙기는 일이 중간인 사람에게 몰리기 쉬우니, 그 수고를 당연하게 여기지 않고 알아주면 부담이 쌓이지 않습니다. |
| 높낮 | 서로 반대라서 초반에 오해가 잦은 조합입니다. 일을 먼저 보는 사람의 지적은 공격이 아니고, 동료를 먼저 살피는 사람의 안부는 시간 낭비가 아닙니다. 피드백에서 내용과 말투를 나눠서 보기로 합의하면 마찰이 크게 줄어듭니다. |
| 중중 | 상황에 따라 둘 다 움직여서 무난합니다. 규칙이 따로 필요하지 않고, 지금 무엇이 급한지만 서로 알려 주는 것으로 충분합니다. |
| 중낮 | 동료를 먼저 챙기는 사람이 분위기를 살피고 중간인 사람이 맞춥니다. 편한 팀이 되는데, 지적할 일을 둘 다 미루기 쉽습니다. 아쉬운 점은 회고 같은 정해진 자리에서 꺼내기로 하면 쌓이지 않습니다. |
| 낮낮 | 둘 다 동료의 상황을 먼저 살핍니다. 분위기는 좋은데 문제 제기가 늦습니다. 일정 지연이나 품질 문제처럼 감정 상할 일이 아니라고 미리 합의한 안건 목록을 두면 말을 꺼내기 쉬워집니다. |

## 3 · 결과물을 낼 때 (빠르게 내보내는 ↔ 끝까지 다듬는)

| 조합 | 문구 |
|---|---|
| 높높 | 둘 다 끝까지 다듬습니다. 품질은 걱정이 없는데 마감이 밀립니다. 어디까지 다듬을지 범위를 시작할 때 정하면 둘의 기준이 같은 곳을 봅니다. |
| 높중 | 다듬는 사람이 마지막 10%를 맡고 중간인 사람이 속도를 냅니다. 잘 맞물리는데, 그 10%가 일정에 안 잡혀 있기 쉽습니다. 검수 시간을 일정에 미리 잡아 두면 그 10%가 일정 안으로 들어옵니다. |
| 높낮 | 한 사람은 80%에서 내보내고, 다른 한 사람은 끝까지 잡고 있습니다. 서로의 방식이 무성의와 비효율로 보이기 쉬운데, 순서를 나누면 맞물립니다. 빠른 사람이 초안을, 다듬는 사람이 마무리를 맡는 흐름입니다. |
| 중중 | 둘 다 범위가 정해지면 그 안에서 조절합니다. 범위만 흐릿하지 않으면 걸릴 게 없습니다. |
| 중낮 | 속도가 나는 조합입니다. 내보내기 전에 한 번 같이 보는 짧은 검토만 정해 두면, 빠져나가는 실수를 줄일 수 있습니다. |
| 낮낮 | 둘 다 빠르게 내보냅니다. 진행은 시원한데 다듬는 사람이 없습니다. 마지막 검토를 누가 할지 정해 두거나, 밖으로 나가는 것만이라도 한 번 더 점검하고 보내면 사고가 줄어듭니다. |

## 4 · 일을 맡길 때 (넘기고 기다리는 ↔ 넘기고 확인하는)

| 조합 | 문구 |
|---|---|
| 높높 | 둘 다 중간을 확인합니다. 확인을 주고받는 것 자체는 문제가 없는데, 둘 다 남의 일까지 들고 있어서 일이 두 사람에게 모입니다. 각자 확인할 범위를 나눠 두면 겹치지 않습니다. |
| 높중 | 확인하는 사람이 묻기 전에 중간인 사람이 먼저 알리면 매끄럽습니다. 보고 주기를 한 번 정해 두면 묻는 일 자체가 줄어듭니다. |
| 높낮 | 한 사람은 중간 상태가 궁금하고, 다른 한 사람은 맡겼으면 들여다보지 않습니다. 확인하는 사람의 질문이 기다리는 사람에게는 재촉으로 읽힙니다. 시작할 때 중간 공유 시점을 한 번만 합의하면, 묻지 않아도 되고 재촉도 아니게 됩니다. |
| 중중 | 크게 틀어질 때만 서로 개입합니다. 잘 굴러가는 조합이고, 어디부터가 크게인지 기준만 한 번 맞춰 두는 것으로 충분합니다. |
| 중낮 | 둘 다 맡기면 잘 안 들여다보는 편이라 서로 편합니다. 대신 어긋난 것을 늦게 발견합니다. 절반쯤 진행됐을 때 한 번 맞춰 보는 자리를 넣어 두면 어긋난 것을 일찍 발견할 수 있습니다. |
| 낮낮 | 둘 다 온전히 맡기고 기다립니다. 간섭이 없어 편한데, 방향이 어긋나면 끝에 가서야 보입니다. 마감 3분의 2 지점에 중간 공유를 하나만 두면 방향이 어긋나도 일찍 보입니다. |

## 5 · 시작하기 전에 (가서 맞추는 ↔ 미리 알아두는)

| 조합 | 문구 |
|---|---|
| 높높 | 둘 다 미리 알아보고 들어갑니다. 준비는 든든한데 착수가 늦습니다. 며칠까지 알아보고 그날 결정한다는 식으로 조사 기한을 먼저 정하면 준비가 길어지는 것을 막을 수 있습니다. |
| 높중 | 준비하는 사람이 바탕을 깔고 중간인 사람이 속도를 맞춥니다. 무난한 조합입니다. 준비하는 사람에게는 다시 정리할 시간이 필요하니, 일정이 바뀌면 먼저 알려 주는 것이 좋습니다. |
| 높낮 | 한 사람은 계획을 세우고, 다른 한 사람은 부딪히며 맞춥니다. 역할이 나뉘면 강한 조합입니다. 초반 조사는 준비하는 사람이, 예상 밖 상황은 맞추는 사람이 받는 식입니다. 준비하는 사람에게는 정리할 시간이 필요하니, 갑작스러운 변경일수록 먼저 알려 주는 것이 좋습니다. |
| 중중 | 둘 다 필요한 만큼 준비하고 시작합니다. 걸릴 지점이 거의 없습니다. |

## 팀 화면 흐름 (07-30, 이음 레퍼런스 기준)

- 팀 페이지가 하나의 URL입니다. 상단에 팀 이름과 `n명 참여 중`, 버튼은 [공유하기] [나도 참여하기] 둘입니다
- **참가는 팀 페이지에서 시작합니다.** [나도 참여하기] → 캐릭터·이름 정하고 검사 → 끝나면 팀 페이지로 돌아옵니다. 개인 결과에서 링크를 넘겨받는 흐름이 아닙니다
- 가운데에 참가자들이 점으로 놓이고 쌍마다 선으로 이어집니다. 선에는 등급 라벨 대신 `맞는 축 n/5` 를 답니다. 등급(천생연분 같은 것)은 판정이라 안 씁니다
- 선을 누르면 그 두 사람의 축별 쌍 규칙 다섯 개가 열립니다
- 아래에 참가자 카드. 본인 결과 요약(제목 문구)과 구간 다섯 개가 보입니다. 원점수는 없습니다
- **참가자 구분은 캐릭터 + 아이템 조합으로 합니다** (07-31). 개인 결과에서는 아이템이 제목 왼쪽에만 붙고, 팀 화면에서는 각자 캐릭터 옆에 자기 아이템이 붙습니다. 캐릭터가 겹쳐도 아이템까지 겹치기는 어렵습니다
- 이름이 팀 안 구분 키입니다. 같은 이름은 참가 시점에 막습니다
- **팀 이름은 팀을 만드는 사람(처음 공유하는 사람)이 정합니다** (07-31 제나)
- **참가자 카드는 팀용 요약까지만 보여줍니다** (07-31 제나). 개인 결과 전문(답 인용 포함)은 본인이 [개인 결과 공유] 링크를 줄 때만 열립니다. 사용자 피드백을 받아 보고 재검토합니다
- **같은 이름으로 다시 검사하면 덮어씁니다** (07-31 제나). 이름이 키라서 최신 결과로 갱신되는 게 자연스럽고, 막으면 실수를 고칠 길이 없습니다
- **팀 데이터는 3개월 보관 후 자동 삭제합니다** (07-31 제나). 저장소가 붙는 시점에 ? 도움말에 [팀 결과는 3개월 보관 후 자동 삭제됩니다] 문구를 함께 넣습니다
