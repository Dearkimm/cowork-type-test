# 팀 쌍 규칙 (초안)

두 사람일 때 축마다 한 단씩 내는 문구입니다. 구간 조합이 높음·중간·낮음에서 여섯 가지라, 축 다섯에 서른 개입니다. 검토 후 `prototype/index.html`에 박습니다.

쓰면서 지킨 것입니다.

- 판정이 아니라 규칙 제안으로 끝냅니다. 궁합 점수를 내지 않습니다
- 어느 조합도 좋은 조합·나쁜 조합으로 읽히면 안 됩니다. 조합마다 굴러가는 방식과 걸리는 지점, 그걸 다루는 규칙 하나를 적습니다
- 높음·낮음 어느 쪽도 착해 보이면 안 됩니다

표기: 높높 = 두 사람 다 높음, 높낮 = 한쪽 높음 한쪽 낮음.

## 1 · 의견이 갈릴 때 (먼저 듣는 ↔ 먼저 말하는)

| 조합 | 문구 |
|---|---|
| 높높 | 둘 다 그 자리에서 말합니다. 결론이 빨리 나는 대신 언성이 쉽게 올라갑니다. 결정 전에 각자 근거를 한 번씩 말하는 순서를 정해 두면 부딪히는 횟수가 줄어듭니다. |
| 높중 | 한쪽은 바로 말하고 한쪽은 중요할 때만 말합니다. 크게 부딪히지는 않는데, 중간쪽이 말을 아낀 안건이 그대로 지나가기 쉽습니다. 먼저 말하는 쪽이 상대 의견을 지목해서 물으면 균형이 잡힙니다. |
| 높낮 | 회의에서 한쪽 목소리만 남기 쉽습니다. 듣는 쪽이 조용한 것은 동의라서가 아닐 수 있습니다. 결정을 하루 묵혔다가 확정하면, 듣는 쪽의 정리된 의견이 들어올 자리가 생깁니다. |
| 중중 | 둘 다 중요할 때만 나섭니다. 평소에는 조용히 굴러가고, 둘 다 나서는 안건이 실제로 중요한 안건입니다. 다만 서로 상대가 말하겠지 하고 넘기는 안건이 생길 수 있어서, 애매한 것은 누가 짚을지 정해 두면 좋습니다. |
| 중낮 | 먼저 나서는 사람이 없는 조합이라 결정이 늦어질 수 있습니다. 안건마다 언제까지 정할지 마감을 걸어 두면, 부족한 추진력을 규칙이 대신합니다. |
| 낮낮 | 둘 다 먼저 듣습니다. 부딪힐 일은 거의 없는데 결정도 잘 안 납니다. 이번 건 결정 담당을 번갈아 맡는 식으로, 정하는 역할을 순번에 붙이면 됩니다. |

## 2 · 일과 사람 사이 (사람을 먼저 보는 ↔ 일을 먼저 보는)

| 조합 | 문구 |
|---|---|
| 높높 | 둘 다 결과부터 봅니다. 용건만 오가도 서로 편하고 속도가 납니다. 대신 둘 다 분위기를 안 살피는 편이라, 팀에 다른 사람이 있으면 그쪽이 지치는 것을 늦게 알아차립니다. |
| 높중 | 일을 먼저 보는 쪽의 담담한 말투를 중간쪽이 무리 없이 받아서 마찰이 적습니다. 급한 시기에는 사람 챙기는 일이 중간쪽에 몰리기 쉬우니, 그 몫도 일로 세어 주세요. |
| 높낮 | 서로 반대라서 초반에 오해가 잦은 조합입니다. 일을 먼저 보는 쪽의 지적은 공격이 아니고, 사람을 먼저 보는 쪽의 안부는 시간 낭비가 아닙니다. 피드백에서 내용과 말투를 나눠서 보기로 합의하면 마찰이 크게 줄어듭니다. |
| 중중 | 상황에 따라 둘 다 움직여서 무난합니다. 규칙이 따로 필요하지 않고, 지금 무엇이 급한지만 서로 알려 주면 됩니다. |
| 중낮 | 사람을 먼저 보는 쪽이 분위기를 살피고 중간쪽이 맞춥니다. 편한 팀이 되는데, 지적할 일을 둘 다 미루기 쉽습니다. 아쉬운 점은 회고 같은 정해진 자리에서 꺼내기로 하면 쌓이지 않습니다. |
| 낮낮 | 둘 다 사람을 먼저 봅니다. 분위기는 좋은데 문제 제기가 늦습니다. 일정 지연이나 품질 문제처럼 감정 상할 일이 아니라고 미리 합의한 안건 목록을 두면 말을 꺼내기 쉬워집니다. |

## 3 · 결과물을 낼 때 (빠르게 내보내는 ↔ 끝까지 다듬는)

| 조합 | 문구 |
|---|---|
| 높높 | 둘 다 끝까지 다듬습니다. 품질은 걱정이 없는데 마감이 밀립니다. 어디까지 다듬을지 범위를 시작할 때 정하면 둘의 기준이 같은 곳을 봅니다. |
| 높중 | 다듬는 쪽이 마지막 10%를 맡고 중간쪽이 속도를 냅니다. 잘 맞물리는데, 그 10%가 일정에 안 잡혀 있기 쉽습니다. 검수 시간을 일정에 미리 넣어 주세요. |
| 높낮 | 한쪽은 80%에서 내보내고 한쪽은 끝까지 잡고 있습니다. 서로의 방식이 무성의와 비효율로 보이기 쉬운데, 순서를 나누면 맞물립니다. 빠른 쪽이 초안을, 다듬는 쪽이 마무리를 맡는 흐름입니다. |
| 중중 | 둘 다 범위가 정해지면 그 안에서 조절합니다. 범위만 흐릿하지 않으면 걸릴 게 없습니다. |
| 중낮 | 속도가 나는 조합입니다. 내보내기 전에 한 번 같이 보는 짧은 검토만 정해 두면, 빠져나가는 실수를 줄일 수 있습니다. |
| 낮낮 | 둘 다 빠르게 내보냅니다. 진행은 시원한데 다듬는 사람이 없습니다. 마지막 검토를 누가 할지 정해 두거나, 밖으로 나가는 것만이라도 하루 묵혔다 보내면 사고가 줄어듭니다. |

## 4 · 일을 맡길 때 (넘기고 기다리는 ↔ 넘기고 확인하는)

| 조합 | 문구 |
|---|---|
| 높높 | 둘 다 중간을 확인합니다. 확인을 주고받는 것 자체는 문제가 없는데, 둘 다 남의 일까지 들고 있어서 일이 두 사람에게 모입니다. 각자 확인할 범위를 나눠 두면 겹치지 않습니다. |
| 높중 | 확인하는 쪽이 묻기 전에 중간쪽이 먼저 알리면 매끄럽습니다. 보고 주기를 한 번 정해 두면 묻는 일 자체가 줄어듭니다. |
| 높낮 | 한쪽은 중간 상태가 궁금하고 한쪽은 맡겼으면 안 봅니다. 확인하는 쪽의 질문이 기다리는 쪽에는 재촉으로 읽힙니다. 시작할 때 중간 공유 시점을 한 번만 합의하면, 묻지 않아도 되고 재촉도 아니게 됩니다. |
| 중중 | 크게 틀어질 때만 서로 개입합니다. 잘 굴러가는 조합이고, 어디부터가 크게인지 기준만 한 번 맞춰 두면 됩니다. |
| 중낮 | 둘 다 맡기면 잘 안 들여다보는 편이라 서로 편합니다. 대신 어긋난 것을 늦게 발견합니다. 절반쯤 진행됐을 때 한 번 맞춰 보는 자리만 넣어 두세요. |
| 낮낮 | 둘 다 온전히 맡기고 기다립니다. 간섭이 없어 편한데, 방향이 어긋나면 끝에 가서야 보입니다. 마감 3분의 2 지점에 중간 공유 하나만 두면 됩니다. |

## 5 · 시작하기 전에 (가서 맞추는 ↔ 미리 알아두는)

| 조합 | 문구 |
|---|---|
| 높높 | 둘 다 미리 알아보고 들어갑니다. 준비는 든든한데 착수가 늦습니다. 며칠까지 알아보고 그날 결정한다는 식으로 조사 기한을 먼저 정하면 준비가 길어지는 것을 막을 수 있습니다. |
| 높중 | 준비하는 쪽이 바탕을 깔고 중간쪽이 속도를 맞춥니다. 무난한 조합입니다. 일정이 바뀌면 준비하는 쪽에 먼저 알려 주세요. 다시 정리할 시간이 생깁니다. |
| 높낮 | 한쪽은 계획을 세우고 한쪽은 부딪히며 맞춥니다. 역할이 나뉘면 강한 조합입니다. 초반 조사는 준비하는 쪽이, 예상 밖 상황은 맞추는 쪽이 받는 식입니다. 갑작스러운 변경만은 준비하는 쪽에 먼저 알려 주세요. |
| 중중 | 둘 다 필요한 만큼 준비하고 시작합니다. 걸릴 지점이 거의 없습니다. |
| 중낮 | 시작이 빠른 조합입니다. 대신 같은 결정을 두 번 하게 되는 일이 생기니, 시작 전에 10분만 아는 것을 같이 정리하면 줄어듭니다. |
| 낮낮 | 둘 다 일단 시작합니다. 착수는 빠른데 중간에 방향을 다시 잡는 비용이 큽니다. 결정한 것을 어딘가에 적어 두는 것만으로도 같은 논의가 반복되는 것을 막을 수 있습니다. |

## 팀 화면 흐름 (07-30, 이음 레퍼런스 기준)

- 팀 페이지가 하나의 URL입니다. 상단에 팀 이름과 `n명 참여 중`, 버튼은 [공유하기] [나도 참여하기] 둘입니다
- **참가는 팀 페이지에서 시작합니다.** [나도 참여하기] → 캐릭터·이름 정하고 검사 → 끝나면 팀 페이지로 돌아옵니다. 개인 결과에서 링크를 넘겨받는 흐름이 아닙니다
- 가운데에 참가자들이 점으로 놓이고 쌍마다 선으로 이어집니다. 선에는 등급 라벨 대신 `맞는 축 n/5` 를 답니다. 등급(천생연분 같은 것)은 판정이라 안 씁니다
- 선을 누르면 그 두 사람의 축별 쌍 규칙 다섯 개가 열립니다
- 아래에 참가자 카드. 본인 결과 요약(제목 문구)과 구간 다섯 개가 보입니다. 원점수는 없습니다
- 이름이 팀 안 구분 키입니다. 같은 이름은 참가 시점에 막습니다
